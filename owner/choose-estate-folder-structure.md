`DERIVED`: the safest names describe a permanent role, not today's project,
program phase, or tool. The main choices are: `owner`, `repositories`, `state`,
`plans`, `decisions`, `ideas`, `evidence`, `practices`, `tools`, `sessions`, and
`archive`.

`DERIVED`: `docs/` is not proposed. It says what a file is, not why it exists,
and would allow the same mixture to grow again.

## What I suggest

`DERIVED`: approve the role names first. Then require each folder README to say
what belongs, what does not, its source of truth, filename rule, and when a file
leaves. Keep only tool-required exceptions at root.

`DERIVED`: use visible `sessions/`, not hidden `.sessions/`. If the kit requires
the hidden name, change the kit before `estate` is created, while the rename
cost is still zero.
