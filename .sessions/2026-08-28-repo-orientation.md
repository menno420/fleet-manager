## 💡 Session idea

**The activity lane's staleness is invisible at the moment it misleads.**
`estate-log.md` carries a `Generated:` timestamp in its header, and a reader who
does not diff it against `git log` has no signal that it predates the work they
are asking about — which is the failure this session hit: the log was two days
old on the estate's busiest day and silently showed none of it. The header
already knows the generation time; what it cannot see is how much has merged
since. A cheap fix with real value: have `refresh` also record the `main` HEAD
sha it was generated at, so any later reader can compare that sha to current
HEAD and see the gap without re-running anything. **Guard recipe:** the writer
is `tools/estate_activity.py` (the header-emitting function that already writes
`Generated:`); the natural test target is a case asserting the recorded sha
matches `git rev-parse origin/main` at generation time.
